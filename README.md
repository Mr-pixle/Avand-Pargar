# آوند | Avand-Pargar

نسخهٔ سروری سامانهٔ مدیریت پروژه، وظایف و همکاری دفتر معماری پرگار. رابط فارسی و راست‌به‌چپ، تم روشن و تاریک و تقویم شمسی.

این مخزن **هیچ عضو، پروژه، تسک، پیام، پیوست، اطلاعات گوگل‌شیت، پایگاه داده یا دادهٔ نمونهٔ شرکت** ندارد. هنگام اولین اجرا فقط حساب مدیر تعیین‌شده در تنظیمات و پیکربندی پایهٔ تیم‌ها، وضعیت‌ها و قواعد ساخته می‌شود. تاریخچهٔ مخزن نیز از همین نسخهٔ پاک شروع شده است.

## امکانات

- پروژه‌ها، مسئولیت‌ها، Phase / Stage / Doc Type / Task / Sub Task و WBS
- نماهای Kanban، List، Calendar و Gantt؛ رنگ Status بر اساس تیم و پیشرفت
- Mind Map قابل ویرایش، شاخه‌های منحنی، چیدمان خودکار، رنگ و شکل، اتصال‌ها و بازگشت تغییرات
- نظارت کارگاهی و گردش تأیید قابل تنظیم، بازدیدها، زمان واقعی شروع و پایان
- کاربران و نقش‌ها، کارهای شخصی، یادداشت، یادآوری، چت و اعلان
- تایم‌شیت، درخواست‌های اداری، گزارش امتیاز، فضای مالی و اداری
- اسناد و پیوندها؛ اتصال اختیاری به Google Sheets برای MDR

## معماری

React 19 + TypeScript + Tailwind/Radix در `src/`؛ Node.js HTTP و PostgreSQL در `server/`. منطق دامنه و مجوزها مشترک است و سرور درخواست‌ها را مجدداً اعتبارسنجی می‌کند. وضعیت در PostgreSQL، فایل‌ها در جداول پایگاه داده و تغییرات زنده با SSE نگهداری می‌شوند. ورود با رمز هش‌شدهٔ scrypt و نشست HttpOnly است. نسخهٔ مخزن همیشه به API سرور متصل می‌شود؛ حالت ورود نمایشی حذف شده است.

## نصب در Windows CMD

پیش‌نیاز: Node.js 22.12+ (نسخهٔ 24 آزموده شده)، pnpm و PostgreSQL 16+.

```bat
git clone https://github.com/Mr-pixle/Avand-Pargar.git
cd Avand-Pargar
corepack enable
pnpm install --frozen-lockfile
copy .env.example .env
notepad .env
```

یک پایگاه داده و کاربر مختص آوند در PostgreSQL بسازید. سپس در `.env`، `DATABASE_URL` و نام/رمز مدیر اولیه را با مقادیر خودتان تنظیم کنید. رمزهای الگو را حتماً جایگزین کنید؛ نام کاربری مدیر باید ۳ تا ۲۴ نویسهٔ انگلیسی کوچک، عدد، نقطه، خط‌تیره یا زیرخط باشد. برای رمز از مقدار یکتا و طولانی استفاده کنید. کاراکترهای خاص رمز در URL اتصال باید URL-encode شوند.

```bat
pnpm run build
pnpm test
pnpm start
```

یا پس از ساخت:

```bat
node --env-file=.env server-dist/main.mjs
```

آدرس پیش‌فرض `http://localhost:8082` است. برای شبکه `HOST=0.0.0.0` تنظیم شده؛ سایر دستگاه‌ها آدرس `http://IP-OF-SERVER:8082` را باز می‌کنند. در فایروال تنها پورت برنامه را برای شبکهٔ موردنظر مجاز کنید؛ PostgreSQL لازم نیست در شبکه عمومی باز باشد. با Ctrl+C سرور متوقف می‌شود؛ اجرای دوباره اطلاعات پایگاه داده را پاک نمی‌کند.

## Docker Compose

Docker Engine/Desktop و Compose موردنیازند. `.env.example` را به `.env` کپی و مقادیر رمزها را تنظیم کنید. Compose از `POSTGRES_PASSWORD` برای دیتابیس استفاده می‌کند؛ در این روش از رمز URL-safe استفاده کنید.

```bat
docker compose up -d --build
docker compose logs -f app
docker compose stop
docker compose start
```

داده‌ها در volume پایدار `pgdata` باقی می‌مانند. **`docker compose down -v` داده‌ها را حذف می‌کند؛ برای توقف عادی استفاده نکنید.** اتصال گوگل برای راه‌اندازی لازم نیست. Dockerfile ارائه شده است؛ آزمون اجرایی Docker در محیط توسعه انجام نشده است.

## تنظیمات

| متغیر | کاربرد |
|---|---|
| `DATABASE_URL` | اتصال PostgreSQL در اجرای مستقیم |
| `HOST`, `PORT` | رابط شبکه و پورت؛ پیش‌فرض نمونه 0.0.0.0:8082 |
| `TARAZ_ADMIN_USERNAME/PASSWORD/NAME` | فقط ساخت مدیر در پایگاه دادهٔ خالی؛ تغییر بعدی این مقادیر رمز موجود را عوض نمی‌کند |
| `TARAZ_COOKIE_SECURE` | روی HTTPS برابر 1؛ برای HTTP شبکهٔ محلی 0 |
| `TARAZ_SYNC_SCHEDULE` | پیش‌فرض off؛ پس از تنظیم اتصال گوگل می‌توان on کرد |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | مسیر مطلق فایل محرمانهٔ service account؛ هرگز در Git قرار ندهید |
| `TARAZ_SYNC_EVERY_HOURS`, `TARAZ_SYNC_HOURS` | دوره و بازهٔ زمانی Sync |
| `TARAZ_WRITEBACK_DELAY_SEC` | تأخیر ثبت تغییرات در Sheets |
| `TARAZ_STATIC_DIR` | اختیاری؛ پیش‌فرض web-dist کنار server-dist |

شناسه‌های `TARAZ_*` برای سازگاری حفظ شده‌اند. `TARAZ_SEED=demo` در این توزیع غیرفعال است.

## بهره‌برداری و پشتیبان

برای اینترنت از reverse proxy با HTTPS استفاده کنید و `TARAZ_COOKIE_SECURE=1` بگذارید. پراکسی باید اتصال SSE را بدون buffering عبور دهد. endpoint سلامت `/api/health` است. برای اجرای دائمی، فرآیند Node را زیر سرویس Windows یا سرویس مدیر فرآیند سیستم‌عامل اجرا کنید.

```bat
pg_dump -Fc -h localhost -U avand -d avand -f avand-backup.dump
pg_restore -h localhost -U avand -d avand_restore avand-backup.dump
```

پشتیبان شامل پیوست‌ها نیز هست. ابتدا بازگردانی را روی یک پایگاه جدا آزمایش کنید. پیش از ارتقا پشتیبان بگیرید؛ نسخهٔ قبلی برنامه و پشتیبان سازگار را برای بازگشت نگه دارید. هیچ فایل `.env`، کلید، خروجی دیتابیس یا CSV/XLSX سازمانی را commit نکنید.

## توسعه و آزمون

`pnpm run check` بررسی TypeScript، `pnpm run build` ساخت فرانت و سرور، `pnpm test` آزمون شروع خالی است. `src/lib/brand.ts` رنگ‌های تیم و پیشرفت را متمرکز می‌کند؛ `src/index.css` رنگ تم و یادداشت‌ها را نگهداری می‌کند. تغییرات رفتار مشترک را در دامنه و کنترل مجوز سمت سرور هماهنگ کنید.

مجوز متن‌باز تعیین نشده است؛ انتشار یا واگذاری حقوق کد نیازمند تصمیم مالک پروژه است.
